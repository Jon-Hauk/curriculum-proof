# Pre-registration: m301-2017 (Mathematics 30-1 Released Items 2017)

Written 2026-10-31, before any Codex answer for this form exists. It is published to [github.com/Jon-Hauk/curriculum-proof](https://github.com/Jon-Hauk/curriculum-proof) before the run starts, so the commit that adds this file is the timestamp. A later edit is a new version; the run is judged against this one.

## Why this run

The pre-registered c30-2019 run ([`PREREG-c30-2019.md`](PREREG-c30-2019.md)) scored 56 of 60, and all four misses had `agree` checks. Three were the right value recorded without its decimal point; one was a modelling assumption the check shared. This run tests the three rules written in response, now in `CODEX-QUEUE.md` under "Recording and check rules":

1. A numerical response is recorded with its decimal point and leading zero.
2. The check compares the recorded string as well as the value.
3. The calculation and the check each list the assumptions that affect the value, and `worked.md` names any assumption they share.

Mathematics 30-1 is a subject the pipeline has worked before (2022 and m301-2019). This run tests the rules, not a new subject.

## What will run

- **Form:** m301-2017, Mathematics 30-1 Released Items 2017 (April 2017). Source, extract and formula-sheet hashes are in `PROTOCOL-m301-2017.md`. 40 machine-scored items: MC 1-28 and NR 1-12. No written response.
- **Answerer:** OpenAI Codex CLI (0.165.0 when this was written; each pass log records the version that ran), model `gpt-6-astra`, reasoning effort `xhigh`, as on c30-2019 and the published runs.
- **Prompt:** `CODEX-QUEUE.md` exactly as in this commit. Compared with c30-2019's prompt, it changes the `answers.json` format line to the recording rule above and adds the "Recording and check rules" section. Nothing else changed.
- **Command,** from the working repository root, with any end time that leaves at least two hours (`-NotBefore HH:mm` may delay the start, for example until a usage limit resets):

  ```
  powershell -NoProfile -ExecutionPolicy Bypass -File .\Invoke-CodexLoop.ps1 -TargetForms m301-2017 -Model gpt-6-astra -ReasoningEffort xhigh -EndTime HH:mm
  ```

- Only this form is targeted. Other prepared forms are not run under this pre-registration.

## Rules for the run

- One run, one attempt per item. A recorded answer is never replaced, and the form is not re-run whatever the score.
- A pass cut off by a usage limit or the slot end is continued by the next pass, which keeps every existing answer and adds only what is missing. A form reopened once for missing artifacts is handled the same way. Both are the same run.
- If the run cannot start (for example, the model is unavailable) and no answer has been written, it may be launched again under this pre-registration. Once any answer exists, that run is the run.
- A `disagree` check is flagged for review, not resolved by re-answering. The score always uses the recorded answers, whatever a review finds.

## Scoring

- After the form is retired: `py -3 grade_form.py m301-2017`. It reads the key from the item-information pages of the local PDF at grade time and writes `SCORE-m301-2017.md` with the total and the miss ids only.
- The matching rule is the one in `grade_form.py`'s docstring, unchanged from c30-2019: MC letters must match; NR values must match after removing whitespace; every value a key lists is accepted; a blank answer is a miss.
- The grader is not Codex.

## Published whatever the result

- `SCORE-m301-2017.md`: machine-scored correct out of 40, and the miss ids.
- The `completion.json` counts: items, answered, checks agree, checks disagree.
- For each miss: whether its check said `agree` or `disagree`, and a one-line cause with no answer values.
- For each `disagree`: its cause, and whether the recorded answer turned out right.
- **Rule 1:** the number of numerical responses recorded with a decimal point. Any miss where the value is right and the recording is wrong counts against the rule.
- **Rule 2:** any recording miss whose check said `agree` counts against the rule.
- **Rule 3:** the number of items where `worked.md` names a shared assumption, and, for each miss caused by an assumption, whether `worked.md` named it as shared. A miss caused by a shared assumption that `worked.md` did not name counts against the rule.
- The number of items whose worked derivation notes a rounding boundary.
- Logged Codex time, from `PROGRESS.md`.
- A new row in `RESULTS.md` and the README results table.

## What this run cannot show

- The form is public, and the April 2017 exam may be in the model's training data.
- One run and one sample per item, so no error bars.
- With 12 numerical responses, the recording rules get a smaller test than on c30-2019's 16. A clean result fits the rules working but does not prove it.
- Rule 3 makes shared assumptions visible; it does not make the check independent. A miss can still come from an assumption both routes share and `worked.md` names.
